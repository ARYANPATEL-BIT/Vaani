## Purpose

Choose and implement the live speech synthesis (TTS) engine for Vaani Week 1.

The architectural decision adopts **Piper** as the active local live speech engine, while establishing a **provider-neutral adapter architecture** so that **Sarvam Bulbul** can be added in a future phase without rewriting caller code or modifying Piper.

---

## Architecture & Provider Boundary

To align with the project's provider patterns (e.g. `vaani.providers.base` used for LLMs), the TTS spike defines a pluggable provider abstraction under `spikes/tts-hinglish/providers/`:

```
spikes/tts-hinglish/
├── providers/
│   ├── __init__.py           # Factory (get_tts_provider) defaulting to 'piper'
│   ├── base.py               # TTSProvider contract, TTSResult, error types
│   ├── piper.py              # Active PiperTTSProvider (local ONNX, zero API key)
│   └── sarvam.py             # Future SarvamTTSProvider adapter boundary stub
├── models/
│   ├── hi_IN-priyamvada-medium.onnx      # 61 MB ONNX model (gitignored)
│   └── hi_IN-priyamvada-medium.onnx.json # Model metadata and phoneme map (committed)
├── audio/
│   ├── piper_romanized.wav   # Generated audio clip (Romanised Hinglish)
│   └── piper_devanagari.wav  # Generated audio clip (Devanagari Hinglish)
├── results/
│   └── piper_run.json        # Execution benchmarks & timing
├── generate_piper.py         # Standalone generation script using provider
├── generate_sarvam.py        # Reference script for future Sarvam testing
├── test_providers.py         # Unit test suite verifying provider decoupling
└── run_spike.py              # Master runner validating pipeline & audio
```

### Provider Contract (`providers/base.py`)
- `TTSProvider(ABC)`: Defines `@property name -> str`, `synthesize(text: str) -> TTSResult`, and `is_available() -> bool`.
- `TTSResult`: Immutable dataclass containing `wav_bytes`, `latency_s`, `sample_rate`, `channels`, `sample_width`, `provider_name`, `model_name`.
- Domain exceptions: `TTSProviderError`, `ModelNotFoundError`, `AuthenticationError`, `SynthesisError`.

### Current Working Provider: Piper (`providers/piper.py`)
- Executes fully on-device using `piper-tts` (v1.8.0) and ONNX runtime.
- Requires **zero external network requests** and **zero API keys**.
- Sub-100 ms generation latency on CPU/Apple Silicon.

### Future Adapter Boundary: Sarvam Bulbul (`providers/sarvam.py`)
- Defines the future integration point for Sarvam Bulbul (`bulbul:v2`, speaker `anushka`, 16 kHz).
- Configurable via `api_key`, `speaker`, `model`, `endpoint_url`.
- In the current Day 5 state:
  - Sarvam was **NOT executed** and **NOT called**.
  - No network requests are made.
  - No credentials or API keys are required from the user or committed.
  - Calling synthesis on unconfigured Sarvam cleanly raises `AuthenticationError`, preserving security and preventing accidental external calls.

- **Latency:** ~0.10s generation time locally.

## Final Decision & Rationale

**Decision:** Adopt **Piper (`hi_IN-priyamvada-medium`)** as the live speech engine for Vaani Week 1.

### Rationale:
1. **P50 Latency Target (< 1,000 ms):** Vaani's conversational pipeline requires low end-to-end latency. Piper's 100 ms generation time leaves sufficient headroom for VAD, ASR, and LLM streaming.
2. **Zero External Dependencies / Hot-Path Safety:** Local inference ensures the live voice path is never blocked by external network jitter, API rate limits, or connectivity loss.
3. **No Credential Dependency:** Works immediately in local developer setups without provisioning paid API keys.
4. **Clean Extension Path:** By introducing `TTSProvider` and `SarvamTTSProvider` adapter stubs, the codebase is prepared to support Sarvam Bulbul whenever cloud credentials and evaluation requirements are introduced.
